# Jev 输入意图路由逻辑审查

本文用于独立审查当前测试分支 `codex/jev-intent-routing`。它描述代码实际保证的行为，不把后续目标写成已完成功能。

## 当前状态机

1. Rime 生成第 1 页候选后，处理层截取最多 10 个候选、当前原始输入和本会话最近提交的上下文。上下文最多保留 128 个 Unicode 字符，并优先从最近两个标点分段的前一个边界开始。
2. 只有显式开启 Jev、存在 API Key 且当前程序位于白名单时，才把请求交给单一后台线程。
3. 新输入递增 `generation` 并替换尚未发送的请求；已经在网络中的旧请求不能取消，但返回后会因代次不一致而被丢弃。
4. Jev 响应必须选择请求中已有的稳定键。完整概率表不得缺项、重复或包含未知项；数值必须有限且位于 `[0, 1]`。
5. 只有不带 Shift、Ctrl、Alt、Super、Hyper 或 Meta 的空格按下事件会尝试消费结果。Space 键释放和组合快捷键不会触发 Jev 提交。
6. 应用结果前再次核对会话、原始输入、第 1 页和候选前缀快照，并执行 `0.60` 最低概率门槛。
7. 候选结果先在 Rime 中高亮，再让同一个空格继续走 Rime 提交路径；`raw_input` 则只提交请求快照里的原始 ASCII 输入，并吞掉本次空格。
8. 任一网络、解析、权限、概率、页码或快照检查失败时，沿用 Rime 原行为。

## 安全与并发不变量

- API Key 只从环境变量读取，不进入日志；包含空白、控制字符或非 ASCII 字符的值不会拼入 HTTP Header。
- 服务端响应不能提供自由提交文本。候选文本和原始输入都必须与请求快照一致。
- 后台线程只读写受互斥量保护的请求和结果，不直接调用 Rime API 或 UI。
- HTTP 只接受 2xx，响应上限为 1 MiB；查询或读取失败均整体拒绝，不解析部分响应。
- 会话移除、失焦和停止服务都会使请求及结果失效；失焦同时清除本地上下文。

## 已知未完成项

候选窗口由 TSF 在按键请求的同步响应中更新。Jev 后台线程返回时，目前没有服务端到 TSF 的主动通知与取数协议。因此当前代码可以在按空格时选中更可能的候选，但不能在用户按空格前把它可靠地移动到可见第 1 位。

这个缺口不能通过后台线程直接调用 UI 来修补，否则会跨线程访问 Rime 和 TSF 状态。后续设计至少需要：主线程消息调度、TSF 异步通知或安全轮询、快照代次确认，以及鼠标、数字键、方向键和高亮位置的一致映射。

整句联合解码、候选 lattice、已提交文字回改、动态置信度和长句评测集也仍属于后续阶段。

## 独立复核重点

- `ParseDecision` 是否对缺失、额外、重复、越界和非数值概率全部失败关闭。
- 新请求与在途旧请求交错时，是否只有最新 `generation` 能成为可消费结果。
- 空格消费结果和新输入调度是否都在现有串行 Rime 调用边界内完成。
- `raw_input` 是否存在绕过请求快照提交任意服务端文本的路径。
- 候选页码、输入或候选内容变化后，旧结果是否绝不会改变高亮或提交文本。
- CI 是否同时通过 clang-format 18、MSBuild 单元测试和 xmake 构建。
