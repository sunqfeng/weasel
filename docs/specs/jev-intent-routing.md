# Jev 输入意图路由规格

## 目标

在不改变 Rime 候选生成机制的前提下，让 Jev 根据已提交上下文、当前输入码和当前候选，判断用户按下空格时最可能想输出的内容：

1. 中文候选；
2. 英文或中英混合候选；
3. 当前原始拉丁字母输入。

Jev 只负责从本地构造的安全选项中选择和排序，不生成任意文本。排序必须结合最近已经提交的文字上下文；概率最高的候选在候选窗口中显示为第 1 位。Jev 不可用、响应无效、置信度不足或结果过期时，必须保持 Rime 原有行为。

## 用户场景

- 用户输入拼音，期望 Jev 结合上文把更合适的中文候选置为当前候选。
- 用户连续输入句子时，期望系统根据前面已经上屏的字段判断后续候选概率，并把最高概率候选排在第 1 位。
- 用户输入英文词或缩写，期望 Jev 能选择候选中的英文，或直接提交当前原始字母。
- 网络慢、API 失败或模型判断不可靠时，用户仍可按原来的方式使用小狼毫。
- 未显式开启 Jev，或当前程序不在应用白名单中时，不发送任何请求，也不改变输入行为。

## 行为约定

### 选择集合

每次请求最多包含当前页前 10 个非空候选，并可额外包含一个 `raw_input` 选项。

`raw_input` 仅在以下条件全部满足时加入：

- 当前输入非空；
- UTF-8 字节数不超过 128；
- 全部字符属于可打印 ASCII；
- 至少包含一个英文字母；
- 不包含空白、控制字符或换行。

候选文本仅作为选项描述发送。模型响应只能引用稳定的选项键，例如 `candidate_0` 或 `raw_input`；响应中的任何自由文本都不得提交给应用。

### 意图类型

本地仅为 Jev 提供提示性类型：

- `han`：包含汉字且不包含拉丁字母；
- `latin`：包含拉丁字母且不包含汉字；
- `mixed`：同时包含汉字和拉丁字母，或无法归入前两类。

类型只帮助模型理解选项，不替代 Rime，也不决定最终文本。

### 应用结果

- 结果必须属于当前请求的选择集合。
- 结果必须与当前会话、当前输入和当前候选快照一致。
- 概率必须为有限数值且位于 `[0, 1]`。
- 概率低于 `0.60` 时忽略结果。
- Jev 返回的候选概率用于稳定降序排列；概率相同时保持 Rime 原顺序。
- 排序时保留每个候选原有的选择标签，并维护显示位置到 Rime 原位置的映射，避免点击候选时选错文字。
- 选择候选时，把排序后的第 1 位映射回 Rime 原候选并高亮，然后沿用 Rime 的提交路径。
- 选择 `raw_input` 时，清除当前组合并通过现有 IPC 响应提交原始输入；本次空格不再交给 Rime。
- 任一检查失败时，不清除组合、不改变高亮，继续执行 Rime 原逻辑。

### 异步和降级

- 请求继续在后台线程执行，不阻塞按键处理。
- 新输入使旧请求和旧结果失效。
- 维持短防抖，避免每个按键都立即请求。
- 连接、发送和接收均设置短超时。
- HTTP 非 2xx、超时、响应超过 1 MiB、JSON 解析失败或字段无效时静默降级。
- API 密钥只从 `TYPESAFE_API_KEY` 读取，不写入日志、配置文件或请求状态。

## 接口设计

新增纯逻辑模块，隔离网络、Rime 会话和选择验证：

- `JevChoiceKind`：`candidate`、`raw_input`；
- `JevChoice`：稳定键、种类、候选索引、文本、文本类型；
- `JevRequestSnapshot`：代次、会话、上下文、原始输入、选择集合；
- `JevDecision`：请求快照、选项键、完整概率分布和稳定排序；
- 构造选择集合、解析响应和判断结果可否应用的纯函数。

网络层只序列化 `JevRequestSnapshot` 并把响应交给纯函数解析。输入法处理层只消费已经验证的 `JevDecision`。

计划修改：

- `RimeWithWeasel/RimeWithWeasel.cpp`：异步请求及按空格应用结果；
- `include/RimeWithWeasel.h`：处理函数签名和会话待提交状态；
- `RimeWithWeasel/RimeWithWeasel.vcxproj`、`xmake.lua`：编译新模块；
- `test/TestResponseParser/*`：路由纯逻辑测试；
- `.github/workflows/ci.yml`：在 MSBuild 构建后执行非交互单元测试；
- `README.md`：说明能力、边界和启用方法。

不修改：

- librime 候选生成算法和用户词典；
- Rime schema；
- TypeSafe Jev 服务端；
- 安装器签名和自动更新机制。

## 代码风格与依赖

- 使用项目现有 C++17 风格和 clang-format 18。
- 继续使用现有 Boost Property Tree，不新增第三方依赖。
- 纯逻辑模块不依赖 WinHTTP、Rime 会话或 UI，便于单元测试。
- 日志不得包含 API 密钥或完整服务端响应。

## 测试要求

单元测试至少覆盖：

- 中文、英文、混合文本分类；
- 合法与非法 `raw_input`；
- 候选数量和长度边界；
- 合法候选选择与合法原始输入选择；
- 概率降序、相同概率保持 Rime 原顺序以及显示位置映射；
- 未知选项、越界索引、缺失字段、非数值/越界概率；
- 低置信度、不同会话、不同代次和快照变化时拒绝应用；
- 原有响应解析测试仍通过且不再等待人工按键。

CI 验证：

- `./clang-format.sh -i`
- `./build.bat arm64 installer`
- `./msbuild/Release/x64/TestResponseParser.exe`
- `./xbuild.bat arm64 installer`

## 完成标准

- 功能默认关闭，原有用户行为不变。
- 开启后，Jev 能在现有中英文候选和合法原始字母之间做选择。
- 只提交请求快照中已有的文本，不能提交模型自由生成的内容。
- 失败、低置信度和过期结果均可靠回退到 Rime。
- 单元测试、格式检查、MSBuild 与 xmake CI 全部通过。
- README 用简体中文准确说明配置、隐私边界和降级行为。
